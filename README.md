# 安全无线控制系统：PC–ESP32–FPGA–STM32 端到端实现

本仓库整理第十届全国大学生集成电路创新创业大赛 Robei 企业命题作品“面向 IoT 边缘节点的 GALS 异步安全加速网关设计”的公开工程资料，获 **华中分赛区二等奖**。

项目以四轮小车为真实执行载体，将网络接入、安全事务处理和物理控制分布到 PC、ESP32、Artix-7 FPGA 与 STM32 四类节点，完成从无线控制请求到实体执行、再到状态回传的双向闭环。

## 系统架构

![系统架构](architecture.svg)

正向链路：

`PC 控制端 → Wi-Fi/UDP → ESP32 → UART → FPGA → UART → STM32 → 电机`

返回链路由 STM32 生成设备状态，FPGA 完成状态校验与响应处理，经 ESP32 返回 PC。PC 仅在来源、帧结构、操作码、解密、CRC 和 sequence 检查通过后更新已确认状态。

当前 `architecture.svg` 是面向公开展示的详细架构图；[`architecture.mmd`](architecture.mmd) 是便于后续编辑的 Mermaid 简化架构源文件。

## 硬件平台

![硬件平台概览](docs/images/hardware-overview.jpg)

- **FPGA 处理节点**：Robei Artix-7 开发板，器件为 Xilinx XC7A50T；
- **无线通信节点**：ESP32-WROOM 开发板；
- **设备控制节点**：STM32F103 控制板；
- **执行与供电**：四轮移动底盘、电机驱动与独立电源模块。

硬件照片、接口角色和供电说明见 [硬件平台说明](docs/hardware.md)。

## 模块职责

### PC 控制端

- 构造控制请求并发起 UDP 通信；
- 执行请求侧的加密和帧封装；
- 接收、解密并校验返回帧；
- 只有在完整校验通过后更新设备状态，避免将发送命令误当作实际执行结果。

### ESP32 通信节点

- 建立 Wi-Fi 连接并完成 UDP 双向收发；
- 在网络数据报与 FPGA UART 数据流之间进行透明桥接；
- 不解释车控业务语义，减少通信层与安全事务层之间的耦合。

### FPGA 安全事务节点

- 使用 Verilog-2001 实现串口数据接收、协议解析/封装与事务状态控制；
- 完成 CRC、sequence、操作码及异常状态检查；
- 完成 AES / SM4 密码模块的接口适配与事务集成；
- 将通过验证的控制请求转换为 STM32 控制帧，并处理返回状态；
- 生成加密响应并经 ESP32 返回 PC。

### STM32 执行节点

- 解析 FPGA 下发的控制帧；
- 通过 PWM 和 GPIO 驱动电机；
- 生成真实设备状态并返回 FPGA；
- 在通信超时或链路失联时执行安全停车，最终将 PWM 置零。

## 关键设计决策

系统设计强调职责分层，而不是把全部功能堆叠到单一设备：

1. ESP32 只承担网络接入和透明桥接，避免通信固件成为业务状态的第二来源；
2. FPGA 负责密码事务、帧校验和控制事务，使安全检查位于执行链路之前；
3. STM32 负责最终物理执行和失联停车，使安全停车不依赖 PC、Wi-Fi 或 FPGA 持续工作；
4. 状态回传以 STM32 生成的实际状态为起点，PC 不使用“已发送命令”替代“已执行状态”。

详细说明见 [关键设计决策](docs/design-decisions.md)。

## 验证方法与结果

项目采用分层验证，避免用单一类型的测试替代完整系统证据：

- **软件层**：协议、密码调用、状态过滤和异常路径回归；
- **FPGA 层**：pytest、RTL 仿真和综合后通信验证；
- **实现层**：器件、时序、DRC 和约束检查；
- **硬件层**：STM32 直接控制、完整链路失联停车和负向异常注入。

当前公开验证摘要：

- Python 回归：**907 项通过，1 项跳过**；
- FPGA pytest：**73 项通过**；
- RTL 与综合后 UART 入口到出口 no-force 测试：**10/10 通过**；
- 实现器件：`xc7a50tfgg484-1`；
- 时序结果：**WNS 0.536 ns，WHS 0.006 ns**；
- 较早资格产物还完成了 AES / SM4 STOP 压力测试、STM32 静默停车和完整链路失联停车测试。

这些数字保留在 README 中用于给出可核查的验证摘要；更完整的测试条件、证据层级和边界说明见 [验证方法与证据层级](docs/verification.md)、[验证结果摘要](EVIDENCE.md) 与 [公开证据索引](docs/evidence-index.md)。

## 项目范围与说明

- AES / SM4 密码核心来自公开参考实现；本项目的 FPGA 工作集中在接口适配、事务控制、协议处理、系统集成、故障定位和验证，不声明从零设计密码算法核心；
- GALS 是参赛作品的正式命题名称。本公开仓库主要记录端到端控制系统、密码事务集成和分层验证结果，不以公开材料单独证明完整时钟域划分或所有 CDC 实现细节；
- 离线软件测试、RTL / 综合验证和真实硬件资格测试属于不同证据层，不能互相替代；
- 比赛后期存在 AES 精简配置，不能与完整 AES / SM4 开发基线描述为同一个 bitstream；
- 超声波实体未安装，仅完成接口、冻结向量和软件 / RTL 模拟验证，不声明真实距离测量通过；
- 本仓库经过脱敏处理，不包含真实密钥、Wi-Fi 凭据、授权令牌、完整固件、bitstream 和未处理原始日志。
